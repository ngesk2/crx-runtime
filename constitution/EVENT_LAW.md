## Article 1 — Event Ontology

### 1.1 Definition

An **event** is an atomic, immutable record of something that occurred within the constitutional system. Events are the sole primitive from which constitutional truth is constructed.

### 1.2 Event Properties

Every event MUST have:

```yaml
event:
  event_id:          uuid          # Unique, content-addressed
  event_type:        string        # From declared classification
  timestamp:         timestamptz   # When recorded (not when occurred)
  aggregate_id:      uuid          # Entity this event belongs to
  aggregate_type:    string        # Entity class
  event_data:        jsonb         # Event payload
  causation_id:      uuid          # What caused this event
  correlation_id:    uuid          # Conversation/session identifier
```

### 1.3 Immutability

Once committed to the event store, an event MUST NEVER be modified, deleted, or superseded. Event correction is performed by appending a new event, never by mutation.

## Article 2 — Event Classes

### 2.1 Constitutional Event

```yaml
event_class: constitutional_event
authority_class: CONSTITUTIONAL_LAW
replay_class: full_replay
verification_required: true
projection_allowed: true
description: Events that establish or modify constitutional state
examples:
  - DOCUMENT_IMPORTED
  - CONSTITUTIONAL_AMENDMENT
```

### 2.2 Governance Event

```yaml
event_class: governance_event
authority_class: CREATOR_RESEARCH
replay_class: full_replay
verification_required: true
projection_allowed: true
description: Events that record governance decisions and policy
examples:
  - GOVERNANCE_DECISION
  - POLICY_CHANGE
  - RATIFICATION_EVENT
```

### 2.3 Observation Event

```yaml
event_class: observation_event
authority_class: TEMPORARY_OBSERVATION
replay_class: conditional_replay
verification_required: false
projection_allowed: true
description: Unverified observations of external state. Not truth until verified.
examples:
  - OBSERVATION_CREATED
  - DOCUMENT_OBSERVED
  - CANDIDATE_CLAIM_CREATED
```

### 2.4 Inference Event

```yaml
event_class: inference_event
authority_class: AI_GENERATED_ANALYSIS
replay_class: non_replayable
verification_required: false
projection_allowed: true
description: Events generated by model inference. Never constitutional truth.
examples:
  - INFERENCE_CREATED
  - SUMMARY_GENERATED
  - EMBEDDING_CREATED
```

### 2.5 Projection Event

```yaml
event_class: projection_event
authority_class: AI_GENERATED_ANALYSIS
replay_class: derived
verification_required: false
projection_allowed: true
description: Events that record projection computation results.
examples:
  - PROJECTION_REBUILT
  - QDRANT_UPSERTED
  - INDEX_REBUILT
```

### 2.6 System Event

```yaml
event_class: system_event
authority_class: CONSTITUTIONAL_LAW
replay_class: full_replay
verification_required: true
projection_allowed: true
description: Infrastructure and lifecycle events that are part of constitutional operation.
examples:
  - SYSTEM_EVENT
  - AGENT_BOOT
  - AGENT_READY
  - AGENT_BOOT_FAILURE
  - CONSTITUTIONAL_INCIDENT
```

## Article 3 — Event Class Rules

### 3.1 Authority Assignment

| Event Class | Authority Class | May Produce Truth |
|-------------|----------------|-------------------|
| constitutional_event | CONSTITUTIONAL_LAW | Yes |
| governance_event | CREATOR_RESEARCH | Yes (governance domain) |
| observation_event | TEMPORARY_OBSERVATION | No (until verified) |
| inference_event | AI_GENERATED_ANALYSIS | No |
| projection_event | AI_GENERATED_ANALYSIS | No |
| system_event | CONSTITUTIONAL_LAW | Yes (operational truth) |

### 3.2 Replay Classification

| Event Class | Replay Behavior | Purpose |
|-------------|----------------|---------|
| constitutional_event | Full replay | State reconstruction |
| governance_event | Full replay | Policy reconstruction |
| observation_event | Conditional | Verification only |
| inference_event | Non-replayable | Not part of constitutional state |
| projection_event | Derived | Recomputable from events |
| system_event | Full replay | Operational audit |

### 3.3 Verification Requirements

| Event Class | Verification Required | Gate |
|-------------|----------------------|------|
| constitutional_event | Yes | Full 5-check gate |
| governance_event | Yes | Full 5-check gate |
| observation_event | No | Tagged unverified |
| inference_event | No | Tagged AI_GENERATED_ANALYSIS |
| projection_event | No | Tagged derived |
| system_event | Yes | Origin verification |

## Article 4 — Event Lifecycle

### 4.1 Lifecycle Stages

```
Creation → Validation → Verification → Storage → Projection → Auditing
```

1. **Creation:** Event is formed with all required fields
2. **Validation:** Event passes schema validation against its declared class
3. **Verification:** Event passes class-specific verification gate
4. **Storage:** Event is committed to authoritative event store
5. **Projection:** Event may be projected to Qdrant or other caches
6. **Auditing:** Event is verifiable through replay and witness

### 4.2 Event Promotion

An event may change class only through an explicit promotion event:

```
observation_event
    ↓ (verification passes)
CLAIM_CREATED (constitutional_event)
```

Promotion requires a new event recording the class change, referencing the original event_id.

## Article 5 — Event Registry

### 5.1 Declared Event Types

Every event_type used in the system MUST be declared in this registry. Undeclared event types are constitutional violations.

```yaml

  constitutional:
    - DOCUMENT_IMPORTED
    - CLAIM_CREATED

  governance:

    - OBSERVATION_CREATED

    - INFERENCE_CREATED
    - SUMMARY_GENERATED

    - SYSTEM_EVENT
    - AGENT_BOOT
```

### 5.2 Registration Requirement

Any code that emits or consumes events MUST register its event types here before deployment. The constitutional compiler (CONSTITUTION_COMPILER_SPEC.md) will enforce this at build time.
