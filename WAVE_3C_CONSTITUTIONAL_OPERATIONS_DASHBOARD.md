**Philosophy (user):** "Build the Constitutional Operations Dashboard driven entirely by PING's registries and event stream." It is a *control center*, not a business admin panel.

---

## 1. Philosophy

The dashboard is a **read-only projection surface** over PING's operational registries + canonical event stream. It:
- Consumes PING-owned operational signals (health, queue depth, replay, connector health, telemetry, deployment state).
- Embeds HPP-defined business projections (PostHog panels) as **read-only** panels — never redefines them.
- Creates **no new authority**. It is a view, not infrastructure (WAVE_3A5 §9).

This is the product→platform moment: PING observes runtime; HPP defines meaning.

## 3. Data Model (what feeds the dashboard)

```
PING Operational Registries (generated by HPP compiler, consumed by PING):
  RuntimeRegistry      → runtime/persistent_runtime.py
  TenantRegistry       → bootstrap/manifest.yaml
  DeploymentRegistry   → deploy/Dockerfile + infra blueprints
  CapabilityRegistry    → notification/capability_resolver.py (+ generated by P040)

PING Event Stream (canonical, source of truth):
  storage/postgres/models.py (Event: event_id hash, producer_id, correlation_id, causality_id, schema_version, build_witness_hash)
  api/main.py /events  → dashboard reads

PING Telemetry:
  notification/metric_events.py → /metrics → prometheus

HPP Projections (embedded, read-only):
  PostHog (mirror of canonical events) → Marketing/Growth/Revenue panels
```

The dashboard reads these. It does **not** write business state, define events, or compute KPIs.

---

## 4. PostHog Relationship

- PostHog is a **projection** of canonical events (BUSINESS_INTELLIGENCE_BOUNDARY §2).
- The dashboard may embed PostHog panels (Marketing/Growth/Revenue) as **read-only iframes/views**.
- PING delivers the canonical→analytics projection (Event Generator, WAVE_3B P003); HPP owns the event *definitions*.
- The dashboard never calls PostHog *ingestion* with new business events — only mirrors what PING already delivered.

## 7. Build Prerequisites (read-only dependency)

The dashboard can be built **only after**:
1. **P002 Capability Registry Generator** (WAVE_3B) — so CapabilityRegistry page has a generated source.
2. **P003 Event Generator** — so PostHog projections (Marketing/Growth/Revenue) are populated.
3. **`/health` delegation** (WAVE_3A5 §3) — so Health page shows live state, not static JSON.
4. **DriftDetector / RuntimeFingerprint** (WAVE_3A5 §9, *views*) — optional enrichment pages.

Until P002/P003 land, the dashboard's Authority/Capability/Marketing/Growth/Revenue pages would be empty. This is consistent with WAVE_3B's deterministic order (generators first, dashboard last).
