## Phase 6 — Configuration Ownership

### Constitutional Ownership Hierarchy

**Target:**
```
Credential Store (Vault)
         ↓
   SecretAdapter
         ↓
Canonical Environment (.env)
         ↓
   Docker Compose
         ↓
     Runtime
```

### Current State

**SecretAdapter:**
- Exists in `runtime/constitutional/secret_adapter.py`
- Used by: `qdrant_projection_worker.py`
- Not used by: Most other workers

**Environment Variables:**
- `.env.example` - Template with defaults
- Multiple `.env` files referenced but not centralized
- Docker compose files define environment directly

**Docker Compose:**
- Multiple compose files with inline environment
- Some hardcoded credentials
- Inconsistent variable names

**Runtime:**
- Workers use `os.getenv()` directly
- Some use SecretAdapter
- Duplicated configuration functions

### Ownership Issues

1. **No Single Canonical Environment**
   - Multiple `.env` files
   - Docker compose defines environment inline
   - No clear source of truth

2. **SecretAdapter Not Universal**
   - Only used by projection worker
   - Other workers bypass it
   - Fallback to environment variables

3. **Runtime Defines Configuration**
   - Workers have `get_postgres_config()` functions
   - Configuration duplicated across files
   - No shared configuration module
