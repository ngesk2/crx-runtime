## Sovereignty Analysis

### Does Qdrant contain any information that cannot be recovered elsewhere?

| Data in Qdrant | Also in Postgres? | Sovereign? |
|---|---|---|
| Vector embeddings (768-dim floats) | **No** — embeddings are computed during projection, not stored in Postgres | **Partially** — embeddings are derived from event text and model weights. With same model + same text, embeddings would be identical. |
| Event metadata (event_id, event_type, etc.) | **Yes** — stored in Postgres events table | **No** — Postgres is authoritative |
| Payload hash | **Yes** — derived from event data | **No** — recomputable |
| Content hash | **Yes** — stored in event_data.content_hash | **No** — stored in Postgres |

### Verdict: Qdrant owns ZERO sovereign information.

Every piece of data in Qdrant can be regenerated by re-running the projection worker against Postgres events with the same embedding model. The only cost is compute time (~2 minutes for 500 events).
